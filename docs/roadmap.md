# «Хто є хто»: roadmap

PWA для гри компанією, коли один телефон передають по колу. Працює офлайн, без бекенду, акаунтів, реклами й хмарних сервісів.

**Стек:**
- Svelte 5 (runes) + Vite + vite-plugin-pwa.
- Плюс `@sveltejs/vite-plugin-svelte`: без нього Vite не компілює `.svelte`-файли. Погоджено.
- Тести — обов'язкові для всього (рішення 12): юніт-тести на вбудованому `node:test` для всієї логіки в `src/lib` з порогом 100% рядків, гілок і функцій (`npm run test:coverage`); e2e на Playwright (`@playwright/test`, лише для тестів, у гру не потрапляє) для екранів і браузерних API — у двох рушіях: Chromium (як Android) і WebKit (як Safari на iPhone). Іконки генеруються один раз і комітяться готовими файлами.

**Робочий процес:**
- Кожен крок — окремий коміт у стилі `feat: …`, `fix: …`, `docs: …`.
- Після кожного кроку **ревізія на слабкі місця**. Знайдене виправляю й перевіряю знову, доки не залишиться зауважень. Потім звіт: що знайдено, що виправлено, які питання може вирішити тільки ти. Далі зупинка й чекаю підтвердження.
- `git push` тільки після твого «так».

## Структура (цільова)

```
src/
  data/questions.json      ← чернетку пише Claude, після схвалення — твій
  lib/questions.js         ← читання, значення за замовчуванням, перевірка схеми
  lib/state.js             ← логіка гри: фільтр, перемішування, черга, бали, збереження
  lib/wakelock.js
  lib/photos.js            ← IndexedDB, стискання, накладання шаблону
  templates/*.svg          ← шаблони для фото
  screens/                 ← Setup, Rules, Categories, Grid, Card, Summary
  App.svelte, main.js
tests/*.test.js            ← node --test
scripts/generate-audio.mjs
public/audio/{id}.mp3      ← необов'язково
docs/roadmap.md
```

`state.js` і `questions.js` не імпортують Svelte: це чисті функції, сховище передається параметром. Компоненти тримають стан у `$state` і викликають ці функції.

## Правила гри

Тут зібрано все, що логіка має робити однозначно. Усе погоджено.

- **Порядок місць.** Гравці вводяться за годинниковою стрілкою: гравець `i+1` сидить ліворуч від гравця `i`, а праворуч сидить `i−1`. Список замкнений у коло.
- **Черга.** Хід переходить до наступного гравця після будь-якої дії з карткою: «Відповів(ла)», «Пропустити», «Правильно» чи «Неправильно». Черга спільна для всіх категорій.
- **Дві ролі на кожній картці** відраховуються від гравця `i`, чия черга:
  - **хто відповідає** — поле `answerer`;
  - **про кого питання** — поле `about`.

  Значення однакові для обох полів. За замовчуванням `answerer` — `self`, а `about` — `answerer`, тобто людина відповідає про себе:
  - `self` — той, чия черга, тобто `i`;
  - `left` — `i+1`;
  - `right` — `i−1`;
  - навпроти — такої ролі немає (рішення 13): у колі на 3, 5, 7 гравців її неможливо визначити однозначно;
  - `answerer` (лише для `about`) — та сама людина, що відповідає;
  - `pick` — той, чия черга, сам вибирає будь-кого, крім себе. Якщо `pick` стоїть в обох полях, «про кого» не може бути тим самим, хто відповідає. Удвох вибору немає, тож другий гравець підставляється сам.

  Приклади:
  - «Що гравець ліворуч любить їсти найбільше?» — `answerer: self`, `about: left`: ти вгадуєш про сусіда;
  - «Чи вміє готувати той, чия черга?» — `answerer: right`, `about: self`: гравець праворуч відповідає про тебе;
  - «Що робить тебе щасливим?» — `answerer: pick`: вибраний тобою гравець відповідає про себе.
- **Імен у тексті немає.** Роль пишемо словами: «гравець ліворуч / праворуч», «вибери будь-кого», «той, чия черга». Про інших — у чоловічому роді («гравець не з'їв би»), питання до тебе — безособово («Коли тобі востаннє було щасливо?»), тож форм на кшталт «з'їв(ла)» немає. Імена й фото видно лише в підписі над карткою: «Відповідає: Оля · той, чия черга → Про кого: Тарас · гравець ліворуч». Фігурні дужки `{…}` у тексті валідатор не пропускає.
- **Хто з нас** (`type: who`). Питання до всіх: на рахунок «три» кожен показує пальцем на когось. Ролей і балів немає.
- **Вгадування й бали.** Картка з `type: guess`, де той, хто відповідає, і той, про кого питання, — різні люди. Людина, про яку питання, каже, чи вгадали. Окремої ролі ведучого немає: «✅ Правильно» чи «❌ Неправильно» натискає той, хто тримає телефон. Бал отримує той, хто відповідав. Якщо при `n = 2` обидві ролі випали на одну людину, картка показується без балів, як звичайне питання.
- **Черга** завжди йде від того, чия черга, до `i+1`, незалежно від того, хто відповідав.
- **Два гравці.** Лівий і правий сусід — та сама людина. Це коректно, нічого не ламається.
- **Вичерпання.** Категорія без вільних номерів показується як «пройдено» і не відкривається. Коли вичерпано всі категорії, гра переходить до підсумку. Завершити гру можна й раніше, кнопкою «Завершити».
- **Зміна гравців під час гри.** Нова гра не починається, номери не перемішуються. Черга продовжується з того самого місця за колом. Якщо поточного гравця видалили, хід переходить до наступного. Бали видалених гравців у таблиці лишаються, з позначкою.
- **Фільтр аудиторії** задається тільки перед новою грою, бо він змінює N у кожній категорії. Категорія, де після фільтра не лишилося питань, не показується.

## Питання: концепція

Мета гри — познайомитися ближче через питання, які люди не ставлять одне одному просто так. Більшість карток про **іншу людину**. Тон теплий, з гумором, але без насмішок, і безпечний для 8-річної дитини.

| Категорія | Ролі | Бали | Прийом |
|---|---|---|---|
| 🔮 Вгадай | ти відповідаєш про іншого | ✅ | поставити себе на місце іншого |
| 🔄 Що про тебе знають | інший відповідає про тебе | ✅ | побачити себе очима іншого |
| 👆 Хто з нас? | усі показують пальцем | — | гумор і спільні впізнавані звички |
| 🧠 Згадай | ти згадуєш про іншого | — | спільні спогади зближують |
| 💛 Скажи приємне | ти про іншого | — | сказати вголос те, що зазвичай мовчимо |
| 💬 Відкрийся | про себе, глибше | — | поступове відкриття, за «36 питаннями» Арона |
| 🌈 Якби… | про себе | — | уявні ситуації показують цінності |
| 🎭 Покажи! | дія | — | розрядка між глибокими питаннями |

- Бали лише в «Вгадай» і «Що про тебе знають», бо тільки там є правильна відповідь.
- Окремі набори (для пар, 18+, для друзів) лежать у [backlog.md](backlog.md).

## Етапи

### 1. Roadmap ✅
- **Результат:** цей документ.
- **Готово, коли** ти підтвердив план і відповів на відкриті питання.

### 2. Прототип ✅ (каркас, екрани категорій і карток, плюс клікабельний UI решти екранів)
- Каркас Vite + Svelte 5; модель стану; `questions.js`.
- `questions.js` бере значення за замовчуванням із `meta.fieldDefaults` і перевіряє схему. Помилку показує зрозумілим текстом із номером питання.
- Екран «Вибір категорії»: сітка з емодзі, назвою, описом і лічильником «залишилось N».
- Екран «Сітка карток»: номери від 1 до N, під сіткою розкривається питання.
- **Готово, коли:**
  - `npm run dev` відкривається на телефоні в локальній мережі;
  - показано всі категорії й справжні питання;
  - використаний номер затемнюється;
  - тест перевіряє справжній `questions.json`: `id` унікальні, усі категорії існують, `type` з дозволеного списку (`open`, `choice`, `activity`, `guess`, `who`), `audience` лише `all` або `kids`, `answerer` і `about` з дозволеного списку, у guess ролі різні, у `who` ролей немає, у категоріях з `scoringCategories` лише guess, у тексті немає `{…}` і форм на кшталт «з'їв(ла)», кожна категорія зі `scoringCategories` існує.
- Коміт `feat: prototype`.

### 3. Логіка гри ✅
- Для кожної категорії відповідність «номер → id питання» тасується методом Фішера–Єйтса.
- Derangement щодо минулої гри. Порівняння йде за `id`: питання, яке було в обох іграх, не отримує свій минулий номер. Якщо минулий номер тепер більший за N, збігу бути не може.
  - Спершу кілька випадкових спроб: для повного збігу наборів одна спроба вдається з імовірністю близько 1/e, тож у середньому досить трьох.
  - Якщо спроби не вдалися, запасний алгоритм міняє місцями конфліктні пари. Розв'язок існує для будь-якої категорії з двох і більше питань.
  - У категорії з одного питання збіг дозволений.
- Використані номери, черга, бали, продовження після перезавантаження. «Нова гра» з підтвердженням перемішує номери заново.
- Під час відновлення стан очищається від того, чого вже немає. Якщо питання прибрали з `questions.json`, його номер вилучається, а гра не падає.
- **Готово, коли** `npm test` проходить. Що перевіряють тести:
  - кожна відповідність — бієкція на 1…N;
  - 10 000 ігор поспіль без жодного збігу зі спільними питаннями минулої гри;
  - зміна набору питань через фільтр і через правку `questions.json`;
  - категорія з одного й з двох питань;
  - пропуск лишає номер використаним;
  - черга переходить по колу для 2–8 гравців;
  - зміна гравців під час гри;
  - відновлення стану, зокрема з пошкодженого чи старого формату.

### 4. Решта екранів ✅ (зроблено разом із прототипом UI; збереження всіх екранів — у кроці 3)
- **Налаштування:**
  - 2–8 гравців у порядку, як вони сидять, з перестановкою кнопками ↑↓ і видаленням;
  - ім'я не може бути порожнім, однакові імена дозволені з попередженням;
  - фільтр «Уся родина / Лише діти»: «Уся родина» показує `all`, «Лише діти» показує `all` + `kids`;
  - «Режим з балами», за замовчуванням вимкнений;
  - голос браузера (етап 8);
  - фото гравців (етап 6).
- **Правила:** `meta.rules` показуються один раз перед першою грою. Потім їх можна відкрити з меню.
- **Картка питання:** текст від 20 px з підставленими іменами. Над текстом «Відповідає: Оля · про Тараса» — ім'я в підписі, тож відмінок не важливий. Якщо є `pick`, спершу кнопки з іменами «Хто відповідає?» або «Про кого?». Для `who` над текстом «Усі разом: на рахунок три покажіть пальцем». Кнопки «Відповів(ла)» і «Пропустити». Якщо є `tip`, під карткою згорнута «Підказка для дорослих».
- **Підсумок:** скільки питань відповіли і скільки пропустили, без переможця. Звідси можна почати нову гру.
- **Готово, коли:**
  - повну гру можна пройти від налаштувань до підсумку, вичерпавши всі категорії або кнопкою «Завершити»;
  - лічильники «залишилось» сходяться;
  - після перезавантаження на будь-якому екрані гра продовжується з того ж місця.

### 5. Режим guess і бали ✅
- Після відповіді кнопки «✅ Правильно» (+1 бал тому, хто відповідав) і «❌ Неправильно». Бал одразу видно поруч з ім'ям, з короткою анімацією «+1».
- Бали нараховуються тільки в категоріях з `meta.scoringCategories`, тільки коли режим з балами ввімкнений, і тільки для `type: guess` з різними ролями. Якщо хоча б одна умова не виконана, на картці звичайні кнопки «Відповів(ла)» і «Пропустити».
- У підсумку з'являється таблиця балів.
- **Готово, коли** тести покривають:
  - усі п'ять значень обох ролей для кожної кількості гравців від 2 до 8;
  - що ролі «навпроти» немає;
  - `pick`: себе вибрати не можна, «про кого» відрізняється від того, хто відповідає;
  - збіг ролей при `n = 2`;
  - чергу від того, чия черга;
  - усі умови нарахування балів.

### 6. Фото гравців і шаблони
- **Фото на картці.** На екрані налаштувань кожному гравцю можна додати фото: зняти камерою або вибрати з галереї. Це звичайне поле вибору файлу з `capture`, без нових залежностей. Фото необов'язкове: без нього показуємо кружечок з першою літерою імені.
- **Де видно фото.** На картці питання поруч із «Відповідає» і «Про кого», у черзі «Зараз хід», у таблиці балів.
- **Шаблони.** Фото можна «одягнути» в шаблон. Вибираєш шаблон, підсуваєш і масштабуєш його пальцем, і результат зберігається як нове фото.
  - **Веселі:** корона, вуса, піратська пов'язка, шапка кухаря, маска супергероя, окуляри-серця, вушка кота.
  - **Серйозні:** рамка «Гравець тижня», рамка-медаль, рамка-полароїд, лаври переможця.
- **Звідки шаблони.** Малюємо самі в SVG: так вони легкі (кілька КБ), працюють офлайн і не мають проблем з ліцензіями. Готових безкоштовних наборів з чіткою ліцензією для вбудовування в застосунок майже немає. Можна взяти й частину емодзі з відкритою ліцензією: OpenMoji (CC BY-SA 4.0) або Noto Emoji (OFL). Тоді в README і на екрані «Про гру» треба вказати авторство.
- **Розпізнавання обличчя** для автоматичного розміщення шаблону не робимо. Браузерне API `FaceDetector` не підтримується в Safari, а сторонні моделі важкі. Шаблон розміщуєш пальцем.
- **Приватність.** Фото дітей ніколи не залишають телефон. Вони лежать в IndexedDB, бо localStorage для зображень замалий: стискаються до 320 px у JPEG, приблизно 20–30 КБ кожне. У налаштуваннях є «Видалити всі фото».
- **Готово, коли:**
  - фото знімається, обрізається до квадрата, на нього накладається шаблон, і воно зберігається;
  - фото видно на картці, у черзі й у таблиці балів;
  - фото переживає перезавантаження й працює офлайн;
  - «Видалити всі фото» справді очищає сховище;
  - на iPhone працює і камера, і галерея (перевіряєш ти).

### 7. PWA
- Маніфест і іконки: 192 px, 512 px, maskable і `apple-touch-icon` 180 px. Service worker наперед кешує всю гру.
- Wake Lock діє лише на екранах гри. Він поновлюється, коли вкладка знову стає видимою, і знімається на підсумку.
- **Готово, коли:**
  - гра встановлюється на головний екран Android і iPhone;
  - відкривається й грається в режимі польоту;
  - екран не гасне посеред гри;
  - нова версія підтягується після перезапуску, а збережена гра не губиться.
- На iPhone перевіряєш ти, мені потрібен звіт або скріншот.

### 8. Аудіо
- `scripts/generate-audio.mjs` читає `questions.json` і для кожного питання створює `public/audio/{id}.mp3`. Готові файли пропускає. Тексти без імен і без форм у дужках, тож озвучуються як є.
- Рушії на вибір:
  - **Piper** з моделлю `uk_UA-ukrainian_tts-medium`: локально, без акаунта, далі WAV перетворюється в MP3 через ffmpeg;
  - **Azure F0** з голосом `uk-UA-PolinaNeural`: ключі в `.env`.
- Кнопка «🔊 Прослухати» з'являється тільки тоді, коли файл для цього питання є. Список наявних файлів збирає вбудований у `vite.config.js` плагін на кілька рядків, без нових залежностей. Тож мережевого запиту немає, і кнопка не блимає.
- **Де лежить аудіо.** На тому самому хостингу, що й гра (Cloudflare Pages). Сторонні адреси (raw.githubusercontent, jsDelivr) не використовуємо: там обмеження на кількість запитів і налаштування доступу між сайтами (CORS), а для офлайну файли однаково треба зберегти на телефоні.
- **Як потрапляє на телефон.**
  - Стартовий кеш service worker містить лише гру, без аудіо, тому встановлення миттєве.
  - Озвучка завантажується у фоні в окремий кеш під час першого запуску. У налаштуваннях видно «Озвучка для офлайну: 120/200» і кнопку «Видалити озвучку».
  - Те, що вже прослухали, теж зберігається. До завершення завантаження кнопка «Прослухати» працює через мережу.
- **Розмір.** Моно MP3 на 32 кбіт/с, для мови якість та сама. Приблизно 20–30 КБ на питання, тобто близько 5 МБ на 200 питань.
- `speechSynthesis` працює лише як запасний варіант, за окремим перемикачем. Якщо українського голосу на пристрої немає, перемикач неактивний і з поясненням.
- **Готово, коли:**
  - скрипт генерує аудіо з нуля і довантажує тільки нові питання;
  - кнопки немає там, де немає файлу;
  - після фонового завантаження все аудіо грає в режимі польоту;
  - обрив мережі посеред завантаження не ламає ні гру, ні те, що вже завантажено.

### 9. Шліфування
- Світла й темна тема за налаштуванням системи. Тепла дитяча палітра, кнопки від 48 px.
- Доступність: контраст WCAG AA, `aria`-мітки, керування з клавіатури, повага до `prefers-reduced-motion`.
- README: вимоги (Node 20.19+ або 22.12+ для Vite 8), запуск, додавання питань, генерація аудіо, встановлення на телефон.
- **Готово, коли:**
  - перевірку пройдено на 320 / 375 / 430 px в обох темах, без горизонтальної прокрутки;
  - найдовше питання з `questions.json` вміщується на 320 px;
  - README покриває всі чотири пункти.

### 10. Публікація
- **Cloudflare Pages** уже підключений до репозиторію: кожен `git push` у `main` запускає збірку й публікацію. Налаштування: команда збірки `npm run build` (не `npm build`), папка результату `dist`, версія Node з файлу `.node-version` (22). Гра відкривається з кореня домену, тож `base` у Vite лишається `/`.
- Cloudflare Pages безкоштовний: необмежений трафік, до 500 збірок на місяць, до 20 000 файлів на сайт. `git push` — лише після твого підтвердження.
- **Готово, коли** гра відкривається за адресою `*.pages.dev` (або твоїм доменом), встановлюється як PWA і працює офлайн.

## Погоджені рішення

1. Додаємо `@sveltejs/vite-plugin-svelte` четвертою залежністю.
2. Гравці вводяться за годинниковою стрілкою, «ліворуч» означає наступного в списку.
3. Окремої ролі ведучого немає. Бал у guess отримує той, хто відповідав, якщо вгадав.
4. **`questions.json`:** стартову чернетку за схемою пише Claude. Після твого схвалення файл вважається твоїм: код його не переписує, а правки вносяться тільки на твоє прохання.
5. **Ролі на картці:** `answerer` і `about` зі значеннями `self`, `left`, `right`, `pick`, а ще новий тип `who` («Хто з нас»). Схема розширена відносно ТЗ, де було тільки `about: left/right`.
6. **Гра суто сімейна.** Аудиторії лише `all` і `kids`. Фільтр «Уся родина / Лише діти». `adults` валідатор відхиляє з поясненням. Дорослий режим і прибрані питання лежать у [backlog.md](backlog.md).
7. **Імен у тексті немає**, лише ролі словами; імена й фото — у підписі над карткою. Більше гумору в питаннях, але по-доброму, без насмішок над кимось.
8. **Бали:** після відповіді «✅ Правильно» / «❌ Неправильно», бал тому, хто відповідав.
9. **Фото гравців** з шаблонами — окремий етап 6, все зберігається лише на телефоні.
10. **Аудіо** лежить на тому самому хостингу (Cloudflare Pages) і завантажується у фоні окремим кешем, моно MP3 на 32 кбіт/с (див. етап 8).
12. **Тести на все:** юніт-тести на всю логіку зі 100% покриттям, e2e на решту (екрани, фото, сховище, перезавантаження) у Chromium і WebKit. `@playwright/test` — п'ята залежність, лише для тестів.
13. **«Навпроти» прибрано:** лише ліворуч, праворуч, на вибір. Питання, що були «про того, хто навпроти», тепер про гравця праворуч.
14. **Дизайн:** шрифт Nunito (OFL, лежить у `public/fonts`, працює офлайн), свій колір у кожної категорії, номери як сорочки карт з переворотом, питання — велика картка поверх екрана, об'ємні кнопки, схема кола на екрані гравців, п'єдестал і конфеті в підсумку, світла й темна тема.
11. **Хостинг — Cloudflare Pages** замість GitHub Pages: ти підключив його до репозиторію.

## Ризики

| Ризик | Що робимо |
|---|---|
| Роль словами розходиться з реальним місцем | Підпис над карткою завжди називає конкретну людину з фото; тест перевіряє, що в кожному guess-тексті названо його роль |
| Помилка схеми в `questions.json` після ручних правок | Валідатор із читабельною помилкою плюс тест на справжньому файлі |
| Derangement неможливий в одній категорії з одного питання | Збіг дозволено. Для двох і більше питань є запасний алгоритм, тести на 10 000 ігор |
| Фільтр або правка `questions.json` змінили набір питань | Відповідність за `id`, перевірка лише спільних питань, очищення збереженого стану під час відновлення |
| На iPhone Wake Lock у встановленій PWA, за повідомленнями WebKit, не працював до iOS 18.4 | Якщо `navigator.wakeLock` немає, показуємо підказку «вимкни автоблокування». Перевірка на твоєму iPhone |
| Safari стирає localStorage сайту, який не відкривали 7 днів | Встановлена на головний екран PWA під це правило не потрапляє. README радить встановити |
| Українського голосу для `speechSynthesis` немає на пристрої | Голос лише запасний варіант. Якщо його нема, перемикач неактивний і з поясненням |
| Piper видає WAV, а MP3 потребує ffmpeg | Скрипт перевіряє ffmpeg і пояснює, як його встановити. WAV-файли в `.gitignore` |
| Великий обсяг аудіо сповільнює встановлення | Аудіо не входить у стартовий кеш; фонове завантаження, моно 32 кбіт/с |
| Стара версія service worker віддає старий код | `registerType: 'autoUpdate'`; оновлення застосовується після перезапуску, збережена гра не губиться |
| Cloudflare збирає старим Node або хибною командою | `.node-version` = 22 у репозиторії; команда `npm run build`, папка `dist` |
| Зміна формату збереженого стану між версіями | Ключ у localStorage має версію. Якщо версія невідома, гра починається з нуля, нічого не падає |
| Фото займають багато місця або браузер їх видаляє | Стискання до 320 px, IndexedDB, `navigator.storage.persist()` у встановленій PWA; якщо фото зникло, показуємо кружечок з літерою |
| Ліцензія на сторонні картинки для шаблонів | Шаблони малюємо самі в SVG; сторонні емодзі лише з відкритою ліцензією й зазначенням авторства |
| Дитина випадково натисне «Нова гра» або «Завершити» | Підтвердження перед обома діями |
